The System page brings resource telemetry, process health, control-bus state, and database status together in one view.

See [Updates & health](/docs/operations/updates) and [Log retention](/docs/operations/retention).

## Top-level status

The first row summarizes:

- CPU utilization and load.
- GPU utilization, temperature, and power.
- GPU memory usage and available capacity.
- System RAM usage, cache, and swap.

Below the summary, charts show utilization, temperature, and power over the selected time range. Hover over a chart to inspect a point. Choose a range from 5 minutes to 24 hours; samples are collected every 10 seconds, and longer ranges are downsampled.

Telemetry history is held in memory and resets on restart. When available, llama-swap's recent performance history is used to backfill CPU and memory data at startup. GPU readings come from the host running llama-dash, which may differ from a remote inference host.

## Memory and thresholds

The memory panel shows GPU allocations and, on supported unified-memory systems, the shared CPU/GPU memory pool. Per-model allocations are estimates measured when a single model load can be isolated; unmeasured models are included in other GPU allocations.

The component list highlights health signals. Use **edit** in the thresholds panel to change the defaults: GPU temperature 90 °C, GPU memory 90%, system RAM 85%, and five-minute average CPU utilization 80%. The log queue is unhealthy by default when any log rows have been dropped. The events panel shows recent threshold breaches and recoveries, model events, and other system events; in-memory system events are lost on restart.

## Runtime panels

The page then breaks down the process state:

- **Control Bus** - active backend, upstream URL, upstream host, `/metrics`, direct-upstream count, and allowed direct targets.
- **Inference Backend** - capability flags for models, running-model state, lifecycle actions, inference pause, logs, and config editing.
- **Inference Backend** also shows queued and dropped request-log writes. Dropped rows mean logging was shed to avoid blocking proxy traffic.
- **Inference Host and CPU Cores** - available hardware details and per-core utilization.
- **Runtime & Database** - uptime, Node version, current git commit, update and pricing catalog status, and SQLite database details.

## Maintenance

Manual prune and compaction controls live on the [Settings](/docs/dashboard/settings) page. The System page is the place to confirm whether the queue, database, proxy, or GPU poller needs attention before running maintenance.
